Behind the scenes

How the live system is laid out, how results are shared, and how abuse is prevented.

Where things run

The website and central server live on Vercel (a hosting company). The probes live on Cloudflare Workers (small programs on Cloudflare’s global network). Your browser talks to Vercel; Vercel talks to Cloudflare; Cloudflare probes talk to the public URL you entered.

Pages and actions

The home page is the dashboard. Running a test is an action sent to the server (not a separate page). The share page is a special URL that contains the encoded results — open it and you see the same globe and table again.

How share links work

There is no database. After probes finish, the server bundles the URL you tested, the timestamp, and every regional measurement into a compact package. That package is turned into a safe string of letters and symbols and appended to the address /r/…. Anyone with the link can decode it in their browser. Treat share links like public notes — do not put secrets in tested URLs.

What a probe actually does

A probe receives a URL and a password. It checks the password, validates the URL again (even if the central server already did), opens the link with a short timeout, reads only enough to measure speed, and returns milliseconds plus an HTTP status code. It does not store or return the page HTML body.

Production: the coordinator

If the central server called each regional probe directly from Vercel, network routing could make every probe look like it ran in the same data center. The coordinator fixes that: Vercel makes one call, the coordinator fans out to all five regions inside Cloudflare, then merges the answers. This only exists on the live site — not on your laptop.

Safety rules (why some URLs are rejected)

Without these rules, a malicious user could use the tool to scan internal company networks. Latencymap only allows ordinary public web addresses, blocks private IPs and localhost, re-checks redirects, limits how much data is downloaded, and caps how many tests one person can run per hour.

Five live regions

The production probes are targeted near these areas:

  • iad — US East (Virginia area)
  • lhr — London
  • sin — Singapore
  • syd — Sydney
  • gru — São Paulo

Each result shows which region ran the test and which Cloudflare data center handled the traffic. The globe uses honest markers — never fake coverage for missing regions.

What this project deliberately does not do

  • No user accounts or logins
  • No billing or subscriptions
  • No scheduled monitoring or email alerts
  • No custom HTTP headers or non-GET methods in the MVP
  • No storing full response bodies

It is a focused demo: one test, clear results, shareable link.
