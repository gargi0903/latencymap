On your computer

Secrets, ports, and how local testing talks to real regions.

One app, real regions

When you run the project locally, the website starts on your laptop. Regional measurements still come from the same five Cloudflare Workers used in production. Set two secrets so the app knows where those Workers live and can prove it is allowed to call them.

What starts when you run dev:local

Settings (environment variables)

Programs read secret settings from a local config file (not committed to git). You need these names for real regional tests:

PROBE_SECRET — the shared password

Think of this as a handshake between the website and the Workers. The website says “I am allowed to run tests” by sending a password. Workers ignore strangers without the password. Use the same non-empty password in your local config, on Vercel, and in every Worker environment.

Unit tests set this password themselves when they simulate Worker calls — you do not need a local config file just to run npm test.

dev:local vs dev:app

dev:local — recommended. Starts the website with local env loaded.
dev:app — Next.js only. Same idea if you already exported env vars yourself.

Your laptop vs the live site

Locally and in production the app calls the same five regional Workers. The difference is where the website itself runs — your laptop vs Vercel.
